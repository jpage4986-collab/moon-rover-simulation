# 底座实体按钮接入记录

## 当前结论

现有工程能把 Unity 的运动数据发给 Mbox100，但没有发现底座实体按钮的输入设备、通信协议或回调接口。因此不能仅靠修改 Unity 场景把这些按钮“连上”。必须先确定按钮由哪个设备采集。

## 现场采集信息

请由硬件现场填写以下信息，或提供照片：

| 项目 | 内容 |
|---|---|
| 底座/控制器品牌与型号 | 待确认 |
| 每个按钮的标签和颜色 | 待确认 |
| 按钮是急停、使能、回零、复位还是其他功能 | 待确认 |
| 按钮线缆最终接到哪里 | Mbox100 / USB / COM / PLC / 其他 |
| PC 插入后设备管理器显示名称 | 待确认 |
| 若为串口，COM 号、波特率、校验、数据格式 | 待确认 |
| 厂商 SDK/说明书/示例程序 | 待提供 |

## 接入决策

- 急停：保留硬件常闭回路，并由控制器切断使能；Unity 只可显示状态，不能替代急停。
- Mbox100 自带按钮：优先按厂商协议或官方中间件配置接入，不能猜测 UDP 数据包。
- USB HID：先用 Windows 的设备管理器、`joy.cpl` 和 Unity Input 确认按钮编号，再写 `ButtonInputAdapter`。
- 串口/PLC：先抓取“按下/释放”两种报文，确认校验和、去抖与断线状态，再转为 `Zero`、`Reset`、`Stop` 等受控事件。

## 验证要求

任何会使平台运动的按钮适配，都必须经过：断开实体平台的协议回放测试、限位/超时测试、急停测试、最终回零测试，再进行低幅度实体测试。没有设备协议和按钮定义前，不应直接向 Mbox100 发送猜测的控制报文。
